# Altioris development prompts

These are edited English translations of the product-development messages from the Altioris work session on 20–21 November 2026. The sequence follows the conversation. Closely related follow-ups are combined where they clarify the same request.

## Typography, navigation, and appearance

**1. Simplify the timetable controls and compare readable typefaces.** Remove the day/week switch. I'll move through the timetable with the arrows. Also remove the decorative images from the exam subjects and keep the navigation controls. Look for upright, legible type with an old university feel. For now, keep the handwritten style inside the timetable and exam screens. Show how each type choice looks in the interface.

**2. Use Philosopher across the portal.** I choose Philosopher. Tune the font sizes and the spacing between controls at 100% browser zoom so they match the feel of the previews. On second thought, use the upright type across every section. Give important text enough weight and make conversation text especially easy to read.

**3. Give the support chat the whole panel.** Remove the panel on the right and let the conversation use the full width. Replace the crest in the conversation with an illustrated support assistant. Make the profile photo control a normal upload so students can choose their own images.

**4. Simplify Settings and polish interaction feedback.** Keep appearance, text size and the current session together, with the session card below the other controls. Remove the extra notification settings, the separate motion setting and the profile block on the right. Restore the compact timetable blocks and remove the extra links under the schedule. Keep comfortable spacing at the default zoom. Make changing a tab or selecting a result feel smooth.

**5. Bring back all the theme choices and smooth out the directory.** I only see the light theme. Restore the theme icons and the dark and system choices, and make changing themes feel smooth. Use the same gentle motion when I select a teacher. Fix the software engineering department filter, and tighten the spacing in Settings so the controls feel grouped.

## Curriculum, directory, and ranking

**6. Build a realistic academic year.** Use publicly available university schedules as references. Populate the timetable and gradebook with realistic subjects, exams and results for a completed year. Vary the teaching days from one to four classes, with space for a reserved day. Make the group labels consistent across the cabinet. Replace the old hard-coded notifications with a working flow.

**7. Expand the faculty directory and illustrate the subjects.** Give each discipline its own teacher and use several departments so the same person doesn't teach everything. Give each teacher a distinct portrait and personal icon. Remove the “Ask a question” block from the faculty profile. Draw each subject icon for the course it represents, and give the support assistant artwork that fits a real help chat.

**8. Use the paper-sticker art direction and publish rankings by session.** Follow the supplied sticker references and replace the old artwork with individually designed illustrations, including the ranking metrics. Publish updated standings after the winter and summer sessions. Let me see how a student's rank has changed. Remove the extra assessment link shown in the gradebook detail.

**9. Improve search, readability, and the profile link.** Fix the light-theme contrast issue. Make the directory search match names, since there is a separate filter for departments. Include a compact biography without making the profile unnecessarily tall. Make the interface at 100% feel as balanced as the 80% example. Move the navigation upward a little, give the profile link its own space, and remove the extra arrow. Use initials on student accounts until someone uploads a photo. Keep the assigned portraits for other uses.

## Live academic events and profile documents

**10. Develop a working notification system.** For the November 19–30 rehearsal, schedule realistic notices about room or timetable changes, online class links, published grades and standings. If a notice says a class moved, move the actual class and check that the new slot causes no overlaps. Use a visible unread indicator, with sound where appropriate. Leave request notifications for a later step and test the scenarios in isolation before changing the live experience.

**11. Correct the exam dates and add a two-sided campus pass.** Check that exams and sessions use the right dates and times everywhere, including the gradebook. Replace the student card with the campus pass shown in my references. Give all 13 students a pass with their assigned photo, and use the supplied flip interaction as the model. Put the pass in the profile, outside “My Documents.”

**12. Add the fictional passport and secondary-school diploma.** Fit “My Documents” into the profile and create both documents for each of the 13 accounts. Use the assigned photo and date of birth for the passport. Set its issue date to the student's 14th birthday.

**13. Refine the campus notices before enabling them.** Aim for about two notices a day through November 30. Mix timetable updates with useful university news and events. Make the message and the received time clear in the details pane. The queue should run while students are signed out. Clear the old request alerts, publish a test notice and check the experience across all 13 accounts. Also give the document and faculty rows their own illustrations and try short first-person faculty biographies.

## Academic records, documents, and requests

**14. Build the request workflow and design the PDFs.** Use the supplied study certificate as inspiration for the typography, layout and finish. Give each request type its own well-designed PDF and a distinct icon. Reuse each template with the student's details, date and document number. Keep the fictional staff member's name and supplied signature in the stationery. Start processing when the student submits. Update the history with the actual times for submission, receipt and processing. Issue the document after roughly two to three minutes, send a notification, and let the student open the PDF from the request.

**15. Remove the old test requests that show incorrect dates.** I want to submit a new request myself and test the flow from scratch. Make sure new requests are actually saved in the database.

**16. Use grades from the appropriate session.** Check the assessment dates and use the most recent session with published results when creating a transcript. The grades in the example are from the wrong period. Also remove the decorative image next to “Ask a question about this request.”

## Student support

**17. Build a student assistant that understands everyday questions.** Research what students commonly ask university support teams. Make the assistant recognize different ways of asking the same thing, common keywords, and follow-up questions. Give clear, useful answers about campus services and the student's records. Save the conversation and start with a clean test chat. Add arrows for moving through the conversation and message read indicators, taking inspiration from messaging apps. A well-placed emoji is fine. Think through the main scenarios and test them.

**18. Make the greeting sound natural.** The opening message currently tells me what I should ask. Please make it feel like someone is greeting me and inviting me to talk: “Hello! How can I help you?”

**19. Simplify the assistant's subtitle.** Keep “Automated assistant” and remove the line about it answering from my account data.

**20. Make the assistant more useful outside of the suggested questions.** Look at public university FAQs and student help bots. “Tell me about the dormitory” should answer the housing question or ask what I want to know. It should only give certificate instructions when I ask for a certificate. Give direct, friendly answers to questions about grades. Use the relevant period and avoid dumping a full session's results when I only ask for a quick answer. If a question is unclear or outside the assistant's scope, handle it politely. Give me a few unusual questions to test by hand.

## Desktop layout and interactions

**21. Polish the directory and academic detail panels.** Clear my test chat and give me a list of questions I can try. Make the email copy control smaller. Look at how HSE University presents staff profiles and write the fictional Altioris biographies in a similar professional style, with education and relevant interests where they fit. Fix the empty space around the desktop details for courses, exams, and study-plan selections. Make the details change smoothly when I switch items, and check the buttons and transitions throughout those screens.

## Phone interface and shared data

**22. Improve the Android layout.** Put the hamburger on the left and make it open a smooth, compact navigation drawer. Rework the settings typography and control sizes. Open selected lessons, exams, and similar details in a compact sheet with the same useful information as desktop, including the teacher when one is assigned. Replace the horizontally scrolling teacher list with a more comfortable phone layout. Keep the desktop interface intact.

**23. Fix the drawer and small-screen controls.** Give the department chevron more space from the edge. Show one clear unread count without a stray dot. Make the close button and the phone's Back gesture reliable every time. Keep request dates and status badges readable at small widths. Animate the open and closed eye when showing or hiding the password on both desktop and phone.

**24. Keep the same accounts and records across devices.** The same permanent logins should work on both desktop and phone. Make request status changes and saved support conversations available on both devices for the signed-in account.

**25. Fix the request card where the status overlaps the date.** Keep enough room around “Sent” and the submission date, including at larger text settings.

## Final usability fixes

**26. Make mobile panels close reliably.** A tester could not close a completed request with the X. Fix dismissal even during live updates and check other tabs for similar freezes. Apply the fix to the shared interface so it works for every account.

**27. Trim the assistant's suggested questions and make the answers dependable.** Remove the difficult test scenarios from the visible menu. Keep practical questions with concrete answers based on the fictional university and the student's records. Asking about the QR pass or dark mode should never return the last teacher's details. Keep a simple greeting and give polite feedback when a question makes no sense. Check the remaining questions against the actual responses and show me what each one will return.

**28. Keep the notification count on the same line.** Give the menu row and desktop sidebar enough room for the label and the badge. Do not wrap the badge onto a separate line. Check desktop and phone with the same shared navigation.

**29. Align the desktop faculty list with the profile panel.** Use the available space beside the selected profile and let the list scroll when needed. Keep the phone layout as it is.
