# Уведомления Altioris

Фоновая очередь Node.js работает, пока запущен сервер. Она проверяет SQLite раз в секунду, даже когда в кабинете никого нет. Для изменения занятия сервер проверяет время, группу, аудиторию и занятость преподавателя. Изменение и связанные уведомления фиксируются одной транзакцией. Повторный запуск сохраняет публикации и отметки о прочтении.

С 19 по 30 ноября 2026 года включительно у каждого включённого аккаунта два плановых сообщения по московскому времени. Утреннее окно начинается в 09:10, вечернее в 15:40. В каждом окне момент публикации выбирается детерминированно в следующие 90 минут. Если вечерний сценарий меняет расписание, оценку или место конкретного студента, академическое сообщение занимает его вечерний слот. Другие студенты получают тему дня. Срочные внеплановые публикации, напоминания о контроле и результаты сессии обрабатываются отдельно. Отметки о заявках находятся в личной истории заявок.

В `npm run dev` учебные рассылки включены. Для режимов запуска через `npm start` значение `ALTIORIS_ACADEMIC_SIMULATION=1` включает тот же сценарий. `ALTIORIS_ACADEMIC_SIMULATION=0` отключает добавление демосценария при следующем запуске. Уже поставленные в очередь записи обрабатываются как обычно. Исторические выпуски хроники хранят время исходного слота. Если сервер пропустил время изменения, очередь проверяет, осталось ли занятие в будущем, прежде чем менять календарь.

Открытая вкладка получает сигнал об изменении через `/api/notifications/stream`. Поток передаёт ревизию, а данные загружаются через API текущего аккаунта. Звук можно включить в ленте. При закрытой вкладке сообщения сохраняются в кабинете и видны после входа.

## Публикация через локальную очередь

Оператор на сервере может поставить событие из JSON командой `node scripts/queue-academic-event.mjs <event.json> --enqueue-only`. Запись `lesson` изменяет указанное занятие, `grade` обновляет оценку, `notice` добавляет информационное сообщение конкретному аккаунту. У события должны быть стабильный `id`, `kind` и при необходимости `at` со смещением или UTC. Для `notice` указываются `owner` (внутренний ID аккаунта), `title` и `body`. Команда с `--list` покажет статус очереди, `--lessons <0|1> <YYYY-MM-DD>` выведет идентификаторы занятий для группы. Доступ к этим операциям требует доступа к локальному процессу и файлу SQLite.
